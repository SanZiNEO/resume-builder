# dsh-resume —— 运行时版本对齐（改这个文件前先读）

runtime   = 目标：desktop 的 nightly feed（会自动更新，运行时版本不固定）。
            参考源码在 E:\Documents\GitHub\resume\deepseek-harness\（master 快照）。
            插件必须假设运行时会变：peerDependencies 用 `*`、preset 引用的行
            照最新 standard.patch.yml 同步；别拿旧包/旧文档当准。

install   = 源码是 TypeScript，构建产物在 lib/：
              pnpm install && pnpm build      # tsdown → lib/{index,policy,client}.js
              pnpm pack                       # prepack = build + 打模板包 → dsh-resume-<v>.tgz
            装进 profile 后由 dsh 的 loader 直接加载 lib/*.js；
            宿主包（@deepseek-ai/*）一律 external，由 dsh 运行时解析提供。

types     = src/types/*.d.ts 是**手抄**的宿主声明，价值是在编译期挡住"API 用错"——
            例如 inject 少写命名空间、把 mounted 的读法写成 .get() 而不是 getSnapshot()。
            注意（2026-11 实测）：`@deepseek-ai/*` 的 0.2.0-rc.2 **已经能从 npm 装上**，
            升级时优先读 node_modules 里的真实 .d.ts，手抄件退为兜底。

契约要点（都对着 0.2.0-rc.2 核对过，改代码前先看这几条）：

  preset    cordis.patch.yml 里 preset 的 `plugins` 是**完整替换**，没有继承；
            registry 挂载审计是"任何一行 import 失败 → 整个 preset 挂载失败"。
            所以列表里的包名必须逐个在目标运行时里存在：
              - @deepseek-ai/dsh-tool-schedule  → 0.2.0-rc.2 不存在（0.2.1-alpha.2 才有）
              - @deepseek-ai/dsh-time-context   → 存在但 standard preset 不挂它
            升级 dsh 后，照新版的 `@deepseek-ai/dsh-web-app/presets/standard.patch.yml`
            重新同步这个列表。

  cwd       0.2.0-rc.2 **没有** `ctx.workingDirectory` 服务（0.2.1-alpha.2 才有）。
            会话工作区读 `agent.session.header.cwd`（guard 的 exec 上是 `exec.agent.session.header.cwd`）。

  tools     `ctx.tools.guard()` 挂普通 ctx = 全局；`ctx.tools.restrict()` **必须在
            agent 作用域**（挂普通 ctx 会抛错）。本插件只加 guard，且把它放在
            preset 里 → 只作用于用该 preset 的会话。

  persona   `dsh-persona` 只能在 preset（agent 作用域）里挂；`prefix` 换掉部署级人设，
            `complete: true` 会把 system prompt 压成只剩这一段（会连带压掉工具指引、
            plan-mode 说明、harness identity）——本插件**不用** complete。
            ⚠ dsh 0.2.1 起 `{{cwd}}` **不再由 loop 注册**，persona 模板里任何 `{{cwd}}`
            都会让提示词组装失败，进而整个 preset 挂载失败——前端只看到
            `Unknown agent preset: resume`，看不出真正原因。本插件已删掉
            `suffix: Your working directory is {{cwd}}.`。`{{model}}` 仍然有效。

  preview   预览是一个 loopback HTTP 服务，固定 `/preview`（端口 39127）。
            应用内形态：插件自己注册的右栏标签页（`ctx.sidebarRightTabs.register`，
            kind `resume-preview`），注册失败时退回官方 `ui-sidebar-browser` 的标签页。
            桌面壳另有一条路：`dsh-overlay/` 往 `apps/desktop/src/main.ts` 插两行，
            挂一个贴主窗右侧的独立 BrowserWindow（见 README「桌面端预览窗」）。
            **不再用 `window.open`** —— 桌面壳里会开不受管的裸窗口。

  bundle    dsh 启动时在 **bundle 层**做兼容性预检（app-boot/profile.ts + plugin-compatibility.ts）：
            对 `dsh.profile.bundles` 里的每个包，读它自己的 package.json 评估
            `engines.dsh`（没有则逐个比对 @deepseek-ai/dsh-* 的 peerDependencies）
            是否满足**运行时版本**。不满足 → 整个 bundle 被跳过（skippedBundles），
            cordis.patch.yml 一行都不进组合；原因只打到 stderr（`dsh: skipping
            profile bundle ...`），桌面端看不见。
            表现：preset 行没注册 → 前端 `agent-preset/not-found: Unknown agent preset`；
            host 行没加载 → 预览端口 39127 无人监听。
            ⚠ peerDependencies **不要钉精确版本**——0.1.0 钉死 0.2.0-rc.2，
            app nightly 一更新整个插件就被静默跳过。
            （2026-11-03 实锤：桌面 "Unknown agent preset: resume" 的真因就是这个，
            与 preset 内容无关；0.2.1 起 peer 全部 `*`。）

  template  模板随包只发 workspace-template.tgz（prepack 由 scripts/pack-template.mjs
            现打；松散的 workspace-template/ 只留在仓库当源，golden 测试也用它）。
            ensureWorkspace 按缺项 `tar -xzf <tgz> data styles ...`（cwd=目标目录）
            直接解到用户目录：一个原生进程写完千余个小文件（Windows 上逐文件
            fsp.cp 极慢）。打包布局固定「顶层就是五个条目」，GNU/bsdtar 按名
            提取行为才一致；产物 tgz 不进 git（*.tgz 已忽略）。
            ⚠ Windows 上 tar 必须显式用 `System32\tar.exe`（两端都这么选）：
            msys GNU tar 被 node 直接拉起时传绝对 Windows 路径会莫名失败
            （创建时 -f 输出经 shell 子进程重定向打不开、提取 exit 2；
            bsdtar 原生处理一切正常）。也别用 `-C` 传 Windows 路径，统一 cwd。

  workspace 会话 cwd = 左栏「工作区」的目录（session header 元数据，创建时定死、之后不可变）。
            默认工作区是系统文档目录；cwd 指到 ~/.dsh/resume 就是旧时代留下的工作区。
            插件在**激活时**和 **setDir 时**调 `ctx.workspaceRegistry.create(dir)`
            （幂等：同一路径返回已有记录、不改用户改过的标题），保证项目目录总有
            对应工作区——新会话 cwd 落在项目里，AGENTS.md 注入、相对路径读写、
            预览、导出才指向同一份内容。
            ⚠ 访问必须走 `ctx.inject(['workspaceRegistry'], cb)` 惰性注入：
            headless 等宿主可能没装配这个服务——直接读属性会因未 inject 抛错，
            写进 preset 行的 inject 会让那一行永远 pending。
            客户端已有两条路在用工作区：引导窗的 `ctx.workspaces.create({ path })`
            和 `enterResumeMode`（建工作区 → startSession → 逐会话设 preset）。

  render    渲染器已从 Python（make.py + src/*.py）迁到 TypeScript，随插件分发、跑在 dsh 的 Node 里
            （src/render/，进程内直接调，不起子进程、不落中间文件）。
            **不需要 Python**；PDF / 长图按能力分层（src/render/pdf.ts）：
            ① 系统 Edge/Chrome（Windows 的 Edge 必装）——puppeteer-core 驱动 headless
               渲染，零下载；探测顺序 Edge→Chrome 的常规安装位+PATH 常见名；
            ② 可选 playwright（100MB+）——运行时动态 import，装了才用；
            ③ 都没有 → 报指引错误（HTML 导出永远可用，Ctrl+P 兜底）。
            两家驱动在 setContent/pdf/screenshot/newPage 形状一致，一套手写接口面对；
            waitForTimeout 只有 playwright 有，等待统一 setTimeout；驱动全部动态
            import（说明符用变量），缺失也不能拖垮宿主行激活。
            ⚠ 桌面端插件进程拿不到 electron：宿主是壳 spawn 的 Node 模式子进程
            （apps/desktop/host-process.ts），壳↔宿主 IPC 是封闭后端集合，没有
            第三方原生动词扩展点——别想当然在插件里 printToPDF。
            `test/golden/*.html` 是原 Python 版生成的参照产物：渲染器改完必须 `pnpm test` 逐字节对齐。
