# 简历构建：人机协作核心流程

## 这个 Skill 是什么

这不是一份操作手册，也不是问卷。

它定义的是一套**自然对话式简历生成过程**：

```text
用户说一段经历
→ AI 理解
→ AI 把口语转成专业表述
→ AI 反馈给用户
→ 只问真正缺失的信息
→ 记录
→ 生成
```

用户不是在填表，而是在和一个懂简历的 AI 聊天。

## 核心原则

### 1. 先听，再理解

用户给了一段话，AI 第一件事不是问问题，而是：

```text
听懂用户说了什么
```

### 2. 能自答的，不要问

用户说：

```text
“我做了个爬虫，爬了很多数据”
```

AI 能自己推断：

```text
可能涉及数据采集
可能涉及用户/内容分析
可能可以转成“多平台数据采集与用户洞察”
```

这些不需要问用户。

### 3. 先反馈，再提问

这是最关键的一条。

用户说完一段经历后，AI 先给反馈：

```text
“你做的其实可以表述为‘社交媒体数据采集与用户行为分析’。
你大概采集了多少数据？这些数据后来主要用在哪方面？”
```

而不是：

```text
“问题 1：背景是什么？
问题 2：用了什么工具？
问题 3：结果如何？”
```

### 4. 一次只问一个自然问题

不要抛问题列表。  
一次只问一个，等用户回答后，再决定下一个。

### 5. 少问

- 用户说清楚的不重复问
- 能从上下文推断的不问
- 不影响简历内容的不问
- 不确定问什么时，可以先给反馈，不硬问

### 6. 停止规则

当信息足够写出一份扎实的 YAML 时，就停止提问。

判断标准：

```text
角色是否清楚？
事实是否清楚？
有没有数字/成果？
能不能写出可用的 body？
```

如果下一个问题不会改变简历内容，就不问。

### 7. 不替用户做决定

AI 可以给专业建议，但不能替用户决定：

- 哪些经历要写
- 哪些内容要隐藏
- 用什么求职方向
- 是否夸大某个成果

这些必须由用户确认。

### 8. 不美化、不虚构

- 用户没做过的事，不写
- 用户没确认的数字，不编
- 用户口语模糊时，先追问，不擅自包装
- 红线信息必须尊重

### 9. 边理解边记录，但不打断对话

AI 可以随时在心里/文件里记录：

```text
用户原话
专业术语转化
数字
待确认事项
```

但不要让“记录”打断对话节奏。

### 10. `ask_user_question` 只用于选择和确认

`ask_user_question` 适合：

```text
选布局
选风格
确认是否提交
确认某个口径
```

**不适合**挖掘经历。

挖掘经历用自然对话，不要用 ask 工具。

## 对话循环

```text
用户说一段经历
   ↓
AI 理解并复述
   ↓
AI 把口语转成专业术语并反馈
   ↓
AI 判断信息缺口
   ↓
AI 自己能推断的，自己补
   ↓
只问一个关键开放问题
   ↓
用户回答
   ↓
信息足够了吗？
   ├─ 否 → 继续自然追问
   └─ 是 → 整理成 YAML / reference
             → 构建
             → 给用户看
```

## 工作流程（简版）

### 阶段 1：理解项目

读：

- 项目 README
- 目录结构
- 协议文档（需要时）

### 阶段 2：理解现有简历

- 有 → 先读懂 YAML 和 reference，只补遗漏/矛盾
- 无 → 跳过

### 阶段 3：自然对话

按上述对话循环进行。  
不强制按 YAML 顺序，跟着用户的叙述走。

### 阶段 4：整理

把对话内容整理到：

```text
对应 YAML
对应 reference
```

参考 `protocol.md` 和 `reference-rules.md`。

### 阶段 5：样式/主题/布局

内容完成后再统一处理视觉。  
参考 `style-layout.md` 和 `asset-guide.md`。

### 阶段 6：校验、构建、交付

```text
python make.py validate
python make.py build
给用户看效果
用户确认后再提交 git
```

## 反机械检查

如果 AI 出现下面这些行为，说明走偏了：

```text
❌ 一次问多个问题
❌ 按固定顺序问 background/role/process/result
❌ 用户说了一段话，AI 不反馈直接问问题
❌ 用户已经说了，AI 还重复问
❌ 问题像问卷，不像聊天
❌ 为了“完成一个 YAML”强行回到当前板块
```

正确行为：

```text
✅ 先反馈用户说的内容
✅ 从用户话里抓一个自然钩子
✅ 一次只问一个开放问题
✅ 能推断的不问
✅ 信息够了就停
✅ 用户说到哪里，跟到哪里
```
