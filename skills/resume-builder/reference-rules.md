# reference 记录规则（reference-rules）

> AI 维护简历记忆和红线时参考。
> 这个项目不额外维护 AI 日志，`reference` 本身就是最好的记录载体。

---

## 1. reference 是什么

每个 YAML 文件末尾可以写：

```yaml
reference:
  这里的内容不会渲染
  构建时会被整段截断
  专门给 AI 读写
```

所以它可以承载：

- 用户原话
- 背景和口径
- 数字来源
- 红线
- 待确认事项
- 项目演进历史

---

## 2. 什么时候写

- 每完成一个 YAML 后
- 访谈过程中问到了重要信息
- 用户给出新数字、新事实、新口径
- 用户说“这个不要写”
- 发现两个文件的口径有冲突
- 项目状态发生变化

原则是：

```text
问完就记，不要等最后一起补
```

---

## 3. 记录什么

不需要固定分类，但建议保留这些信息：

### 用户原话

```yaml
reference:
  用户原话: >
    用户说“我搞了个东西，很多人用”
```

### 专业化表述

```yaml
reference:
  专业化表述: >
    独立完成开源项目，获社区数万播放
```

### 数字与来源

```yaml
reference:
  数字: 2400+ 下载
  来源: CurseForge 588 + Modrinth 1830
```

### 角色边界

```yaml
reference:
  角色: 主导创意与设计，代码由 AI Agent 辅助
  不是: 不是独立完成全部技术实现
```

### 红线

```yaml
reference:
  红线: >
    不写课程作业身份
    不写问卷非本人制作
    不暴露具体隐私信息
```

### 待确认

```yaml
reference:
  待确认: >
    上线收益金额尚未确认，暂不写
```

---

## 4. 红线规则

### 不虚构

- 用户没做过的事情，不写
- 用户没说的数字，不编
- 用户没确认的成果，不擅自写

### 保护隐私

- `personal.yaml` 只保留 `${NAME}` / `${PHONE}` / `${EMAIL}` 占位符
- 真实隐私不写进 YAML
- 不要从 reference 推断真实隐私

### 尊重用户红线

- 读 `personal.yaml` 的 reference
- 如果里面写了“AI 不写 / 不写课程作业 / 不写某个项目”，必须遵守
- 如果发现新内容和旧红线冲突，先问用户

### 不要暴露短板

- HR 角度会问困难，但简历内容扬长避短
- 用户提到的失败/不足，只作为能力成长素材
- 不作为简历正文展示

---

## 5. 口径一致性

一个项目/事实可能分散在多个 YAML 的 reference 中：

```text
personal.yaml
education.yaml
projects/*.yaml
internships/*.yaml
```

修改一个时，要检查：

```text
其他文件里有没有相关口径？
数字是否一致？
角色描述是否一致？
时间是否一致？
```

如果冲突，不要自己选：

```text
先问用户，确认后再统一口径
```

## 6. 参考写法示例

```yaml
reference:
  背景: >
    数字营销战略课程专题，用户选择真实数据演示
  包装: >
    简历不按课程作业呈现，按独立研究项目呈现
  用户原话: >
    “当时就是自己爬的微博数据”
  专业化表述: >
    独立完成多平台数据采集、用户画像建模与跨品牌分析
  数字: 20 品牌 / 7292 用户 / 110 万关注关系
  红线: >
    不写课程作业身份
    不写技术实现细节
    不夸大模型能力
  待确认: >
    无
```

---

## 7. 不要做的事

- 不要把 reference 写成正式简历内容
- 不要删掉用户的原始说法
- 不要因为“看起来不好”就丢掉真实事实
- 不要自己拍板口径，除非用户之前已经确认过
- 不要用一份 reference 覆盖另一份的不同口径
