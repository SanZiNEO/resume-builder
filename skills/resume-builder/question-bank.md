# 提问库（question-bank）

> 这是 AI 在内容访谈阶段使用的提问指南。
> 它不是一个“固定问卷”，而是一套帮助 AI **围绕单个 YAML 深挖信息**的方法。

---

## 使用方式

1. 一次只聚焦一个 YAML。
2. 先问这个板块的主问题。
3. 根据回答继续追问，不要急着跳到下一个板块。
4. 用 `ask_user_question` 工具反复提问。
5. 把用户的重要原话、数字、背景、术语记录到当前 YAML 的 `reference`。
6. 完成后处理 body，再进入下一个 YAML。

---

## 核心原则

### 1. 不预设能力标签

问题库中不写“这个问题是为了挖沟通能力/数据分析能力”。

AI 应该：

```text
从用户的回答中自主发现能力、特质、经验
```

### 2. 记录口语术语和专业化术语

用户往往说得口语化、非专业。

例如：

```text
用户：我就搞了个东西，很多人用。
```

AI 要：

- 继续追问清楚
- 记录用户原话
- 转化成专业化表达
- 在 `reference` 中保留原始说法和专业说法

### 3. 负面问题要有，但导向解决

可以问：

```text
遇到什么困难？
最难的环节是什么？
有没有没做好的地方？
```

但必须继续追问：

```text
怎么解决的？
最后结果怎么样？
你学到/成长了什么？
```

目的是：**扬长避短，不把短板写成简历展示内容。**

### 4. `reference` 不规定固定结构

因为 `reference` 会被截断，不参与渲染。

所以 AI 可以自由组织：

```text
用户原话 / 事实 / 数字 / 术语 / 待确认 / 口径
```

不需要固定 `facts / evidence` 分类。

### 5. 不虚构

- 用户没说过的，不替用户编。
- 数字必须问清楚。
- 角色必须分清楚“自己做的”和“别人做的”。

---

## 通用追问链

每个 YAML 都可以沿着这条链深挖：

```text
背景 → 角色 → 过程 → 困难 → 解决 → 结果 → 证据 → 术语
```

| 环节 | 可问的问题 |
|---|---|
| 背景 | 这件事是什么背景？为什么开始？ |
| 角色 | 你具体负责什么？哪些不是你做的？ |
| 过程 | 你是怎么做的？用了什么方法/工具？ |
| 困难 | 遇到什么困难？最难的环节是什么？ |
| 解决 | 你怎么解决的？有没有调整方案？ |
| 结果 | 最后结果怎么样？有数字/成果/反馈吗？ |
| 证据 | 有没有作品、报告、链接、数据可以验证？ |
| 术语 | 你平时怎么描述这件事？专业上可以怎么说？ |

## 按板块提问起点

### personal（基本信息）

- 求职方向 / 目标岗位
- 到岗时间、地点、状态
- 想重点突出什么
- 有没有必须不写的内容
- 有没有需要弱化的内容

### education（教育）

- 学校、专业、时间
- 主修/相关课程
- 科研、项目、奖项
- 有没有和求职方向相关的经历容易被忽略
- 哪些信息要写进简历，哪些只保留在 reference

### projects（项目）

- 项目背景和动机
- 你的角色：独立 / 主导 / 核心 / 参与
- 具体做了什么
- 用了什么方法、工具、数据
- 遇到什么困难，怎么解决
- 最终结果 / 数据 / 反馈
- 有没有可验证材料（仓库、报告、作品集、链接）
- 用户原话里的“关键词”怎么转成专业表达

### internships（实习）/ work（工作）

- 公司 / 部门 / 岗位
- 主要职责
- 参与或负责的具体项目
- 日常工作里的具体产出
- 数据、成果、客户/用户反馈
- 和团队怎么协作
- 有没有可验证的结果或材料

### skills（技能）

- 每个技能真实的掌握程度
- 在哪些场景实际使用过
- 哪些是“会用但不深”
- 哪些技能有项目/作品支撑
- 用户描述技能时用的口语说法，转成专业表达

### summary（个人总结）

- 核心优势是什么
- 和目标岗位最匹配的点
- 个人特质
- 希望 HR 第一眼看到什么
- 这里最后再问，基于前面所有经历提炼

## 追问技巧

### 1. 用户只说结果，追问过程

```text
用户：我做了个数据分析项目。

追问：你具体分析的是什么数据？
      数据量大概多少？
      你负责分析还是也负责采集？
      最后产出了什么？
```

### 2. 用户说得模糊，追问数字

```text
用户：效果挺好的。

追问：“挺好的”具体指什么？
      有没有播放量、下载量、用户数、转化率？
```

### 3. 用户说“我们”，追问角色边界

```text
用户：我们做了一个网站。

追问：在这个网站里，你自己做了哪部分？
      服务器/前端/内容/设计分别是谁负责？
```

### 4. 用户说口语词，追问专业说法

```text
用户：我整了个爬虫，爬了很多数据。

追问：你说的“爬虫”具体用的什么方式？
      数据存在哪里？
      大概爬了多少条？
      这些数据后来用来做什么？
```

### 5. 遇到负面，追问解决和成长

```text
用户：当时差点没做完。

追问：为什么差点没做完？
      后来怎么解决的？
      最后完成了吗？
      这件事让你学到什么？
```

---

## 记录到 reference

每次问完，把重要内容记到当前 YAML 的 `reference`。

可以是自由格式，但建议至少保留：

```text
用户原话 / 口语表述
数字与可验证信息
角色边界
待确认内容
专业化改写方向
```

不要等最后统一补，问完就记。
