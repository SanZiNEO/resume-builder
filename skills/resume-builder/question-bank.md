# 内部信息缺口检查器（question-bank）

> 这不是“要问用户的问题清单”。
> 这是 AI 在听用户说话时，**心里默默检查的信息缺口**。
> 不要把它当成问卷逐条问。

---

## 使用方式

```text
用户说一段经历
→ AI 心里过一遍下面这些缺口
→ 自己能推断的，自己补
→ 只把真正影响简历内容的关键缺口，用自然对话问出来
→ 一次只问一个
```

## 信息缺口类型

### 1. 事实缺口

用户说的是模糊的，需要补时间、规模、对象。

心里检查：

```text
这件事发生在什么时候？
规模多大？
针对什么对象？
持续了多久？
```

### 2. 角色缺口

用户说“我们”或“做了一个东西”，需要分清边界。

心里检查：

```text
用户本人具体负责什么？
哪些是别人做的？
是独立、主导、核心成员，还是参与？
```

### 3. 过程缺口

用户只说了结果，需要知道怎么做到的。

心里检查：

```text
用了什么方法/工具/流程？
有没有技术或方法上的亮点？
中间有没有调整？
```

### 4. 结果缺口

用户说“效果不错”，需要具体化。

心里检查：

```text
有没有数字？
有没有成果、反馈、下载、播放、用户？
有没有可验证材料？
```

### 5. 困难/成长缺口

心里检查：

```text
有没有遇到困难？
怎么解决的？
最后结果怎么样？
这件事体现了什么能力？
```

注意：困难用于“扬长避短”，不作为简历短板展示。

### 6. 措辞缺口

用户说了口语词，需要转专业术语。

心里检查：

```text
用户原话是什么？
专业上可以怎么说？
两者都要保留到 reference。
```

## 信号触发表

当用户提到某些词，AI 应该自动联想到可能的信息缺口：

| 用户说的 | AI 心里应检查 |
|---|---|
| 爬虫 / 数据 / 采集 | 数据量？来源？用途？ |
| 用户 / 人群 / 画像 | 分析维度？样本？结论？ |
| 项目 / 产品 | 角色？功能？结果？ |
| 平台 / 社区 / 播放 | 规模？反馈？可验证数据？ |
| 我们 / 团队 | 用户边界？协作方式？ |
| 效果不错 / 挺好 | 具体数字？成果？ |
| 做个网站 / 系统 | 技术？功能？实际应用？ |
| 帮别人 / 委托 | 是否可写？是否涉及隐私？ |

## 自然问法示例

### 示例 1

用户：

```text
我做了个爬虫，爬了很多数据
```

机械：

```text
问题 1：背景是什么？
问题 2：用了什么工具？
问题 3：爬了多少？
问题 4：结果如何？
```

自然：

```text
“你做的其实可以表述为‘多平台数据采集与用户洞察’。
你大概爬了多少数据？这些数据后来主要用在哪方面？”
```

### 示例 2

用户：

```text
我搞了个项目，后来效果挺好的
```

自然：

```text
“听起来你有一个实际落地的项目。
当时是你独立做的，还是团队一起？最后有没有你能记得的具体结果？”
```

### 示例 3

用户：

```text
我们做了一个网站
```

自然：

```text
“这个网站里你自己负责的是哪部分？是前端、产品设计，还是整体都参与了？”
```

## 停止规则

当 AI 能回答以下问题时，就可以开始整理 YAML 了：

```text
这件事是什么？
用户做了什么？
有没有结果/数字？
能不能写成一条 body？
```

如果下一个问题不会改变简历内容，就不问。

---

## 反机械检查

如果出现了以下行为，说明不对：

```text
❌ 一次问 4-5 个问题
❌ 按“背景→角色→过程→结果”顺序问
❌ 用户已经说了“我独立做的”，还问“是不是你独立做的？”
❌ 用户说了“爬虫”，不反馈直接问“用了什么技术？”
❌ 为了凑齐问题库，问无关问题
```

正确行为：

```text
✅ 先反馈用户说了什么
✅ 先转成专业术语
✅ 只问一个真正缺的点
✅ 能推断的就不问
✅ 信息够了就停
```
